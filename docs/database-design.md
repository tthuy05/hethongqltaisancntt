## 2. Quy ước chung

- DB object và cột dùng `snake_case`; entity C# dự kiến dùng `PascalCase` và ánh xạ tường minh.
- Khóa chính dùng `bigint GENERATED BY DEFAULT AS IDENTITY`; bảng nối vẫn có khóa chính riêng để truy vết/audit thống nhất.
- Thời gian dùng `timestamptz` theo UTC; giá trị tạo mới mặc định `clock_timestamp()`.
- Tiền tệ/giá trị tài chính dùng `numeric(18,2)`, giữ precision/scale và CHECK không âm; numeric tiền/score phải loại `'NaN'::numeric` vì PostgreSQL cho phép NaN vượt kiểm tra >= 0. Ratio giữ `numeric(5,4)` BETWEEN 0 AND 1.
- Chuỗi dùng `varchar(n)` trên database/client UTF8, giữ nguyên n và API length validation; không đổi semantic limits vì PostgreSQL đếm characters khác UTF-16 units. Null byte không hợp lệ trong PostgreSQL text, cần safe validation/test.
- Enum nghiệp vụ được lưu bằng `varchar` và ràng buộc `CHECK`; mã C# phải ánh xạ cùng tập giá trị.
- Giữ 13 cột `row_version` ở aggregate mutable; map `bytea` NOT NULL, CHECK 16 bytes, application-managed `IsConcurrencyToken()` theo ADR-019. Không native rowversion/xmin/IsRowVersion.
- Master/transaction root không xóa cứng: dùng `is_active` hoặc `is_archived`, kèm thời điểm/người thực hiện khi cần.
- Bảng lịch sử `asset_status_histories`, `maintenance_histories`, `audit_logs` chỉ thêm mới; ứng dụng và tài khoản DB không được `UPDATE`/`DELETE`.
- FK mặc định `ON DELETE NO ACTION`; không cascade-delete dữ liệu nghiệp vụ hoặc lịch sử.
- Unique business key vẫn trim/normalize theo contract. PostgreSQL default UNIQUE không tự case-insensitive: code/serial/employee code dùng `lower(column)` expression unique index (serial/employee nullable giữ partial predicate); username/email dùng unique cột normalized hiện có. Không thêm normalized columns hoặc extension. Collation/casefold thực tế cần kiểm trên Neon trước migration; không copy SQL Server Vietnamese_CI_AS sang PostgreSQL.
- Các cột `created_by_user_id`/`updated_by_user_id` cho phép `NULL` để hỗ trợ bootstrap hoặc tác vụ hệ thống, nhưng nếu có giá trị phải tham chiếu `users(id)`.

### 2.1 Chuẩn hóa dữ liệu

- Thiết kế đạt tối thiểu 3NF: master (`departments`, `asset_types`, `softwares`, RBAC) tách khỏi transaction và history; quan hệ nhiều-nhiều có bảng nối.
- Không lưu `assets.current_user_id`: current holder được suy từ active assignment. Không lưu `software_licenses.used_quantity`: tính từ active license assignments.
- Snapshot status trên aggregate (`assets.current_status`, `maintenance_tickets.status`) được giữ có chủ đích để truy vấn nhanh, nhưng phải cập nhật atomic cùng history.
- JSON chỉ dùng cho snapshot giải thích/audit có schema linh hoạt; field thường filter/join vẫn là cột typed, có FK/index.
- Không dùng generic polymorphic FK cho assignment target; hai FK nullable + XOR constraint giữ toàn vẹn tham chiếu.

## 4. Bất biến và transaction quan trọng

### 4.1 Bàn giao/chuyển tài sản

Trong một transaction duy nhất:

1. Khóa parent asset bằng `SELECT ... FOR UPDATE` trong transaction trước đọc active assignment; mọi assign/return/transfer/maintenance/archive dùng cùng thứ tự lock để bảo vệ cross-workflow invariant.
2. Kiểm tra `row_version`, quyền theo scope và target đang hoạt động.
3. Nếu chuyển: đóng assignment cũ bằng `returned_at_utc/returned_by_user_id`; không ghi đè target cũ.
4. Thêm assignment mới; partial unique index chặn hai assignment đang mở.
5. Cấp phát từ `IN_STOCK` chuyển sang `IN_USE`; transfer của asset đang `IN_USE` giữ nguyên status, chỉ touch row nếu cần concurrency. `row_version` đổi khi row asset thực sự được cập nhật.
6. Thêm `asset_status_histories` khi trạng thái thực sự đổi và thêm `audit_logs` đã redact.
7. Commit; lỗi ở bất kỳ bước nào rollback tất cả.

Thu hồi tương tự nhưng không tạo assignment mới và chuyển asset về `IN_STOCK`, trừ khi workflow maintenance/broken hợp lệ đang chi phối trạng thái. Cấp phát lần đầu yêu cầu `IN_STOCK`; transfer yêu cầu `IN_USE` với đúng một active assignment; asset `MAINTENANCE`, `BROKEN`, `RETIRED` hoặc archived không được cấp phát/transfer.

### 4.2 Cấp license

- Khóa parent `software_licenses` bằng `SELECT ... FOR UPDATE` trước count/validate/write trong transaction READ COMMITTED theo mục 3.15; mọi capacity-changing command theo cùng protocol. SERIALIZABLE alternative cần handling serialization failure, không SQL Server locking hint.
- Đếm `COUNT(*)` assignment có `revoked_at_utc IS NULL AND is_archived = false`; mỗi row là một seat trong MVP.
- Chỉ thêm/cập nhật khi tổng mới `<= total_quantity`; kiểm tra license active/chưa hết hạn và target phù hợp `license_type`.
- partial unique index ngăn cấp trùng license-target đang hiệu lực; `CHECK` bảo đảm XOR target.
- Thu hồi đặt thời gian/người thu hồi, không xóa dòng.

### 4.3 Trạng thái và lịch sử

- `assets.current_status` và `maintenance_tickets.status` là snapshot phục vụ truy vấn.
- Mỗi chuyển trạng thái hợp lệ phải thêm history trong cùng transaction với thay đổi snapshot.
- History là append-only; correction là sự kiện mới, không `UPDATE`/`DELETE` sự kiện cũ.
- State machine chi tiết thuộc service/domain policy; DB `CHECK` chỉ giới hạn tập giá trị, không thay thế kiểm tra transition.

### 4.4 Optimistic concurrency

- API đọc `row_version`, biểu diễn Base64 qua ETag/DTO; lệnh sửa phải gửi lại token.
- EF Core cấu hình `IsConcurrencyToken()` cho `byte[] row_version`/bytea, không `IsRowVersion()` hoặc `[Timestamp]`. Central SaveChanges/interceptor tạo 16 cryptographically random bytes khi Added và regenerate mọi Modified mutable row, giữ original token cho WHERE; 0 affected rows/DbUpdateConcurrencyException trả `409 Conflict`. Update role phải touch user cùng token_version/audit. Seed/bulk/direct SQL write sau này cũng phải theo protocol, không được bypass token.
- Token original cho conditional write phải là version client đã đọc/gửi: validate với row hiện tại hoặc đặt EF OriginalValue từ request token trước SaveChanges. Không lấy token vừa query mới làm original rồi bỏ qua token request, vì như vậy stale client vẫn ghi đè được. Regenerate CurrentValue không được thay OriginalValue.
- API rowVersion/strong ETag/If-Match vẫn Base64 opaque, không fixed counter/timestamp; client không tự sinh token. Archive thiếu If-Match trả `428`, malformed `400`, stale `409`. Không silently retry overwrite.
- Các thao tác đếm liên dòng như capacity license vẫn cần transaction/locking; token riêng lẻ không đủ. ADR-019 chọn giữ binary column thay vì xmin để không đổi baseline/schema/API.

## 5. Dữ liệu khởi tạo dự kiến

Chỉ seed dữ liệu kỹ thuật ổn định bằng migration ở Week 3+:

- Permission code chuẩn theo ma trận phân quyền.
- Ba role baseline `ADMIN_IT`, `SYSTEM_MANAGER`, `TECHNICAL_SUPPORT` và ánh xạ permission đã được phê duyệt; không tự seed thêm actor ngoài scope.

- Không seed dữ liệu tài sản/license mẫu vào production.

Toàn bộ seed và migration hiện là **PLANNED**, chưa được tạo trong Week 2.

Khi seed dùng explicit positive bigint IDs, PostgreSQL identity sequence không tự đồng bộ theo max seeded ID. Initial migration/seed review phải đặt sequence/start phù hợp để generated IDs không trùng seed, verify trên isolated target trước shared apply; không đổi key strategy hoặc tạo ID giả trong task này. ## 6. Sao lưu, retention và quyền DB dự kiến

- Tài khoản ứng dụng chỉ có quyền CRUD cần thiết; lịch sử/audit chỉ `INSERT` và `SELECT` theo vai trò.
- Runtime identity không có owner/DDL/superuser/neon_superuser; migration identity tách riêng do Thủy giữ. Với identity bigint phải grant quyền sequence cần thiết ngoài table privileges; default privileges được review để future migrations không vô tình mở quyền history/audit.
- TLS tới Neon dùng certificate/hostname validation (Npgsql SSL Mode=VerifyFull); không log connection string/password. Recovery/backup tùy Neon project/plan thực tế, chưa verified; khóa mã hóa license không lưu cùng DB.
- Backup có mã hóa, kiểm thử restore định kỳ, RPO/RTO phải được chủ hệ thống phê duyệt.
- Retention audit/history và quy trình archive cần tuân thủ chính sách tổ chức; không purge trước khi có phê duyệt.
- Dữ liệu test phải tổng hợp/ẩn danh; không sao chép production secrets hoặc license key.

## 7. Chiến lược delete, timestamp và history

- **Hard delete:** chỉ cân nhắc cho dữ liệu chưa từng được dùng và không có FK/history, qua quy trình quản trị riêng; API MVP không cung cấp hard delete cho dữ liệu nghiệp vụ.
- **Deactivate:** `departments`, `users`, `asset_types`, `softwares`, `software_licenses`, `replacement_rules` dùng `is_active`; dữ liệu inactive vẫn xuất hiện trong lịch sử nhưng không được chọn cho giao dịch mới. `roles`/`permissions` cũng có `is_active` để quản trị seed/migration, nhưng không được deactivate qua runtime API trong MVP ba role cố định.
- **Archive:** `assets`, `asset_assignments`, `maintenance_tickets`, `license_assignments`, `replacement_recommendations` dùng `is_archived`; service kiểm tra precondition trước archive.
- **Append-only:** status history, maintenance history và audit không update/delete. Assignment/allocation đã đóng cũng được xem là immutable; correction tạo event/record mới có lý do.
- `created_at_utc` có trên aggregate/root và mapping cần truy vết; `updated_at_utc` chỉ có ở entity mutable. Actor chi tiết được lưu ở cột chuyên biệt hoặc `audit_logs`, tránh nhân đôi quá nhiều FK gây vòng bootstrap.
- `created_by_user_id`/`updated_by_user_id` có ở aggregate cần truy vết trực tiếp (`departments`, `users`, `assets`); các aggregate khác dựa trên audit/action actor và field nghiệp vụ. Nếu consistency review yêu cầu actor column đồng nhất hơn, phải thay schema/ERD trước migration.
- Tất cả FK `NO ACTION`; deactivate/archive user/master không làm mất history.

## 8. Chiến lược migration **PLANNED**

Chỉ bắt đầu sau Week 2 review/approval và permission triển khai module; **Primary Migration Owner: Thủy**. Thiện đề xuất/sửa entity module mình nhưng sync trước `dotnet ef migrations add`/`dotnet ef database update`; không tạo/apply hai schema-changing migrations độc lập cùng lúc trên shared Neon.

1. Xác định requirement/schema change.
2. Update database-design.md.
3. Update erd.md nếu schema/quan hệ thay đổi.
4. Review với Thiện và nhận database change lock của Thủy.
5. Modify Entity/Configuration theo contract.
6. Thủy create EF migration nhỏ từ baseline đã sync.
7. Review generated migration/SQL/partial predicates/constraints/NO ACTION/data-loss/permissions; apply thử và test trên isolated PostgreSQL target trước shared apply.
8. Thủy apply lên actual shared Neon qua direct endpoint với migration identity riêng trong cửa sổ đã sync.
9. Smoke test schema/migration history/seed/connection/API, ghi evidence thật và thông báo Thiện.
10. Commit migration cùng docs sau review/gate trong phase implementation được phép, nhả lock; **không commit trong task hiện tại**.

## 9. Cân nhắc hiệu năng

- Query danh sách dùng projection, `AsNoTracking`, filter/sort allow-list và pagination ở SQL; không tải toàn bảng vào memory.
- Index ưu tiên theo use case: business key; asset department/type/status; active assignment; ticket assignee/status; license expiry/capacity; recommendation status/priority; audit time/entity/actor.
- Partial unique index vừa bảo vệ invariant vừa giảm tập index. Predicate EF/SQL phải khớp chính xác nullable/archive semantics.
- Dashboard/report dùng `COUNT/SUM/GROUP BY` ở DB. Chỉ thêm covering index sau khi xem execution plan/query telemetry; tránh index mọi cột sớm.
- Tránh N+1 và lazy loading; report lớn có giới hạn date/row, export theo streaming/batch khi triển khai.
- JSON payload audit/snapshot bị giới hạn; không index JSON tùy tiện. Nếu filter lặp lại, promote field cần thiết thành column typed qua migration review.
- Audit/history tăng không giới hạn cần retention/archive đã phê duyệt; partitioning chỉ xem xét khi volume đo được.
- Transaction giữ ngắn, truy cập aggregate theo thứ tự nhất quán để giảm deadlock; retry chỉ khi command idempotent/an toàn.

## 11. Kiểm tra nhất quán thiết kế

## 12. PostgreSQL compatibility review — Database Platform Change Addendum

### 12.1 Baseline và kết luận

Review ngày **01/10/2026**, sau khi đọc toàn bộ WIP/handoff và database-design, ERD, business rules, use cases, API. **Giữ nguyên 18 tables, 41 FK/relationships, toàn bộ tên/cột/PK/FK/nullable/cardinality**; không thêm refresh_tokens/locations/vendors/notifications/import_jobs/settings hay đổi bigint IDs sang UUID. ERD Mermaid block dùng logical types nên không đổi diagram. Tất cả 18 bảng chỉ đổi physical mapping phụ thuộc engine, không đổi entity/business requirement/API contract; chưa có schema/data/migration để chuyển thực tế.

### 12.2 Mapping và rationale chung

| SQL Server baseline (historical) | PostgreSQL planned mapping | Lý do / impact |
|---|---|---|
| bigint IDENTITY(1,1) | bigint GENERATED BY DEFAULT AS IDENTITY | Giữ numeric PK và toàn bộ FK bigint; không UUID redesign. Identity không thay PK/NOT NULL. |
| nvarchar(n) / varchar(n) | varchar(n), database/client UTF8 | PostgreSQL không có nvarchar; giữ cùng n, API required/length vẫn nguyên. Không đổi field ngắn sang text để bỏ length. |
| nvarchar(max) + ISJSON | jsonb + object/array CHECK cho bốn snapshot cũ | PostgreSQL không có ISJSON; valid structured JSON, giữ nullable và shape semantics (ADR-020). Không thêm JSON index. |
| decimal(18,2), decimal(5,4), decimal(9,4) | numeric với cùng precision/scale | Không float/precision loss; bổ sung NaN rejection cho money/score >=0 vì khác engine. |
| bit / defaults 0,1 | boolean / false,true | Boolean predicates/CHECK/partial indexes đổi literal, không đổi nghiệp vụ. |
| datetime2(7) / SYSUTCDATETIME() | timestamptz / clock_timestamp() | UTC instant, microsecond precision; clock_timestamp là thời điểm thực, CURRENT_TIMESTAMP là transaction-start nên không dùng thay ngầm. |
| uniqueidentifier correlation_id | uuid | Chỉ correlation field có sẵn, không đổi primary keys. |
| varbinary(max), varbinary(32) | bytea; hash CHECK 32 bytes khi có | Giữ ciphertext/hash binary; bytea không có length(n) nên CHECK bảo toàn SHA-256 size. |
| native rowversion | bytea app-managed token 16 bytes + IsConcurrencyToken | Không native SQL Server type; 13 cột/concurrency API opaque giữ nguyên, no xmin/column removal (ADR-019). |
| filtered indexes / INCLUDE | partial indexes với PostgreSQL WHERE / INCLUDE giữ nguyên | PostgreSQL hỗ trợ cả hai; không thêm clustered index hoặc redesign toàn index strategy. |
| case-insensitive collation unique | unique lower-expression hoặc normalized column hiện hữu | Default PostgreSQL UNIQUE case-sensitive; DB vẫn chặn concurrent case-variant duplicate, không chỉ API check. |
| LEN(last4), UPDLOCK/HOLDLOCK | char_length(last4), SELECT FOR UPDATE parent-row protocol | Hàm/hint không portable; giữ masking length và capacity/assignment atomicity. |

System fields CreatedAt/UpdatedAt/AssignedAt/ReturnedAt/StartedAt/ResolvedAt và các cột `_at_utc`, `_from_utc`, `_to_utc`, `_end_utc` đều là **timestamptz**. Backend dùng DateTime Kind=Utc hoặc DateTimeOffset Offset=0, không bật legacy timestamp behavior; DB/session/report clock phải xác minh UTC. Timestamptz lưu instant, không lưu timezone gốc. `purchase_date`/`warranty_end_date` vẫn **date** (DateOnly). License `purchased_at_utc`/`starts_at_utc`/`expires_at_utc` vốn là instant nên giữ instant, không đổi expiry semantics sang date-only chỉ vì tên API. Timestamp round-trip test so precision microsecond, không hứa 100ns. [Npgsql datetime mapping](https://www.npgsql.org/doc/types/datetime.html), [PostgreSQL time functions](https://www.postgresql.org/docs/current/functions-datetime.html).

### 12.4 Naming, comparison và index review

- Table/column vẫn lowercase snake_case, C# PascalCase với explicit EF mapping. UQ_/IX_ trong mục 3 là logical labels cũ; physical names map lowercase tương ứng để không phụ thuộc quoted mixed-case identifiers. Npgsql quote lowercase identifiers được phép, không đổi table/column spelling.
- Chưa biết actual Neon collation/locale/PostgreSQL version; **NOT VERIFIED**. Vietnamese_CI_AS audit chỉ là lịch sử. Kiểm Unicode/tiếng Việt/accent/case, supplementary characters và normalized keys trước migration; không hứa lower/casefold locale khác sẽ giống hoàn toàn SQL Server. Không thêm citext/unaccent/pg_trgm extension trong task này.
- DB unique expression giữ case-insensitive codes/serial; canonical trim/normalize application cũng bắt buộc. Username/email unique trên cột normalized hiện hữu; không tạo cột mới. Search literal case-insensitive dùng parameterized `EF.Functions.ILike`, escape `%`, `_` và escape character; giữ keyword/sort/page/DTO contract. Translation và execution plan phải test trên actual provider ở Week 3. [PostgreSQL expression indexes](https://www.postgresql.org/docs/current/indexes-expressional.html), [Npgsql translations](https://www.npgsql.org/efcore/mapping/translations.html).
- Đã rà asset_code, serial_number, asset_type_id/current_status, owning_department_id/current_status; assignment asset_id/current predicate/history; maintenance asset_id/status/open status; license expiry; replacement asset_id/current/budget. Giữ các key/order/payload INCLUDE có sẵn, chỉ đổi expression/predicate literals khi engine cần. Status-only query có thể cần measured index review sau MVP; không tự thêm index/đổi workload ngay.
- Partial WHERE predicates giữ nullable/open/archive semantics và phải khớp query EF; nullable serial/employee unique không dùng NULLS NOT DISTINCT. Existing INCLUDE hỗ trợ PostgreSQL; không thay bằng clustered index hoặc thêm GIN cho jsonb. [PostgreSQL partial indexes](https://www.postgresql.org/docs/current/indexes-partial.html), [Npgsql indexes](https://www.npgsql.org/efcore/modeling/indexes.html).
- Monetary/score CHECK thêm `<> 'NaN'::numeric`; constrained numeric(p,s) giữ range/precision. Ratio BETWEEN0AND1 đã từ chối NaN. [PostgreSQL numeric special values](https://www.postgresql.org/docs/current/datatype-numeric.html).

### 12.5 JSON, provider và deployment impact

`jsonb` tự validate syntax nhưng còn cần object/array CHECK để không nới baseline ISJSON sang scalar/JSON null; SQL NULL vẫn cho phép ở audit fields. Redaction/allow-list/size limit trước serializer; không duplicate keys. Key order/whitespace không là business requirement. Hash-chain nếu có phải canonicalize redacted payload theo schemaVersion trước persistence, không hash jsonb::text. Chỉ audit_logs/replacement_recommendations đổi JSON physical type; không thay API/action/permission, không thêm table/index (ADR-020). [PostgreSQL JSON types](https://www.postgresql.org/docs/current/datatype-json.html).

Provider plan dùng `UseNpgsql(...)` đọc `ConnectionStrings:DefaultConnection` từ user-secrets/env `ConnectionStrings__DefaultConnection`; code pattern ở architecture chỉ là PLANNED.
